# 解读一致性指标

先区分两个问题：“大家是否标出了相同的项目？”以及“在所有可选项目中，一致程度是否超出随机期望？”

| 指标 | 回答什么 | 解读要点 |
| --- | --- | --- |
| Jaccard | 共同拒绝数除以至少一人拒绝的项目数 | 两个空集按约定记为 1。 |
| F1 | 共同拒绝数的两倍除以两个拒绝集合大小之和 | 对称；两个空集记为 1。 |
| Precision / Recall | 共同拒绝数分别除以评分者 A / B 的拒绝数 | 有方向性，不意味着其中一人是金标准。 |
| Kappa | 在共同项目全集上，扣除随机期望后的一致性 | 需要元数据；两位评分者用 Cohen，多于两位用 Fleiss。 |
| ICC(2,1) | 个体评分者给出的连续质量分数的绝对一致性 | 只纳入所有评分者均有有限分数的数据集；应报告样本量。 |

例：A 拒绝 {1, 3, 5}，B 拒绝 {3, 5}。Jaccard 为 **2/3**，F1 为 **4/5**，precision 为 **2/3**，recall 为 **1**。这不能单独说明两人均保留了多少个 epoch。

## 为什么没有数值？

- 只有一份评分的数据集不能估计评分者间一致性。
- 计算 kappa 前勾选 **Use EEG metadata for kappa**，并提供共同的 QC 前文件。未知通道、越界索引不能当成一致。如果所有人对所有项目只给出同一类别，期望一致率为 1，kappa 无定义。
- **试次编号：** v1.3.0 的 CSV 记录当前 epoch 序号。如果存在 `EEG.etc.EEGdojo.TrialID`，基于元数据的 kappa 会把记录解释为映射后的 ID。如果两者不一致，先在独立分析副本中对照内嵌 QC 记录统一编号，再解释 trial kappa。
- ICC 至少需要两份评分完整的数据。全部分数没有变异时也可能无法估计。应报告缺失原因和样本量，不要用 0 替代无法估计的数。
